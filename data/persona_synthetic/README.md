# Synthetic persona corpus

Everything under `data/persona_synthetic/` is **fictional and synthetic**. No real
person is depicted, and **no private/persona data is ever stored here**. This
corpus exists so the Guardian-Angel (GA) personalization pipeline can be built and
tested honestly — on CPU, with no model downloads and no network access.

This directory is intentionally **not** gitignored (unlike `data/persona_private/`,
which is). A tiny generated sample is safe to commit; large generated corpora are
cheap to regenerate and may be left untracked locally.

## What's in it

Generated by `src/guardian_research/experiments/persona/prepare_corpus.py`:

```
v0/
  manifest.json                     # data_class=synthetic, fictional=true, counts
  personas/<key>/
    PRINCIPAL.md                    # the persona's values/preferences/style
    docs/train/<i>.md               # in-style documents (with GA annotations)
    docs/holdout/<i>.md             # held-out documents for evaluation
    summaries.jsonl                 # per-document summaries
    qa_log.jsonl                    # elicitation Q&A (principal answers, in-voice)
```

Three deliberately distinct fictional personas (terse engineer / ornate essayist /
plain-spoken organizer) give stylometry and preference-prediction real, but
entirely invented, signal to recover.

Intra-file annotations mark load-bearing spans, e.g.:

```
<!-- GA: important: preference (drink) -->
<!-- GA: style: signature-closer -->
```

## How to (re)generate

```bash
uv run ga persona prepare --out data/persona_synthetic/v0
uv run ga persona eval     --out data/persona_synthetic/v0      # variant comparison
uv run ga persona questions --out data/persona_synthetic/v0     # active-learning Qs
uv run ga persona run +exp=persona_dynamic_eval seed=0          # full RunResult
```

Generation is fully deterministic given `--seed`. The numbers are template-driven,
not learned, so do not read scientific significance into them — they exercise the
*tooling*, and a null/negative result on a variant is reported honestly.

## Why synthetic (the doctrine)

A real GA's data — your emails, notes, sessions, real `PRINCIPAL.md` — is the most
sensitive data you have. The GA design keeps it on the principal's machine and
never uploads it. To develop the tooling without ever touching private data, we
fabricate personas here. A real principal's `PRINCIPAL.md` should be filled from
`planning/PRINCIPAL.template.md` and kept out of the repo entirely.
